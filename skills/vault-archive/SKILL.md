# 档案库工作流程

Wood 的档案库在 `D:\Data\Personal`。我负责 `01个人档案/`。建档与更新都按这里来。

规则不是铁的：Wood 随时可以口头改，改了以他为准，并更新本文件。

## 边界

- `01个人档案/` 完全归我，读 + 写，也是写给他看的。
- `03日记/` 是他写的，我只读，不写、不改。
- `02人生导师/` 不归我，不读、不写。
- `00系统模板/` 只读。
- 库根目录保持干净：不放规则文件，不放处理日志。

## 写档案的五条

1. 只写事实。不解读、不评价、不给建议。
2. 每条信息带来源：`（来源：2026-10-04 日记）`。
3. 原话照录，不改写、不润色。
4. 不确定 → `⚠️ 待核验`。不编。
5. 矛盾 → 不覆盖、不替他选，列出来问。

## 动作一：建档

**核心是深度访谈，不是填表。** 这是整件事里最容易被做砸的地方——如果只是问一圈基本事实，产出的是身份证复印件，不是档案。

- 一次只问一个问题，等回答。
- 不接受模糊回答。他说"还行"，就问"还行"背后是什么。
- 每个模块结尾必须问一组**不好意思说出口的**问题——那组才是档案值钱的地方。
- 顺序：`01-个人宪法` 先做，它是其余模块的地基。（他也是从 repository 里学到"先做 01"。）
- 一个问题可以跳过，跳过就跳过，不追问第二遍。
- 想到什么问什么，随时可以被打断；话题切换不用收尾。

题库：见 `访谈题库.md`。

产出：填充 `01`–`09` 维度档案；写 `00-索引.md`。`10-编年史` 和 `04-医学事实` 不走访谈（见下）。

## 动作二：更新档案

口令「更新档案」。他随时说。

1. 读 `01个人档案/` 现状。
2. 读 `03日记/` 里上次维护之后新增的日记。
3. 两件事：
   - **编年史**：日记的主要去处，按日期追加。
   - **维度档案（01–09）**：只有出现**持久性的事实变化**才改（体重变了、换工作、定了新日程）。日常流水账不进维度档案。
4. 汇报：读了几篇、改了哪些、哪些要他拍板。

**克制原则**：宁可少改维度档案，多写编年史。他说过日记对维度档案帮助不大。

## 特殊文件

- `04-医学事实.md`：只存体检报告**原文数字**。不接受他口头复述的版本——他有把 5 条说成 2 条、把"1 个月复查"说成"半年"的记录。有出入以原文为准并提醒他。初始内容由他手动粘贴。
- `10-编年史.md`：日记的归宿。格式：
  ```
  ## 2026-10-04 星期日

  - 完成软考中级摸底卷
  - 建立日记系统 （来源：03日记/2026-10-04 星期日.md）
  ```

## 格式约定

- 维度文件（01–09）开头写 3–5 行「摘要」。
- 隐私级别标注（借自 ai-context-vault-cn 的分级）：`L1` 可给任何云端 AI / `L2` 私密，需脱敏 / `L3` 高敏，只在本地用。他的 `04-医学事实` 是 L3，`09-财务` 至少 L2。
- 脱敏写法：`[已脱敏]`、`[当前公司]`、用范围代替精确值（`月入 [2-3万]`）。

## 还没定的事

- 编年史越来越长的解法（按年分文件 + 只留信号 + 年度复盘）——已提出，等他点头。
- 他的库没有「AI 交互偏好」模块（原项目有）。要不要加。
- 精简版主档案：一份可以贴给任何 AI 的压缩版（原项目的 `档案模板.md` 是干这个的）。他的知识库场景用得上。
